# 人格 / 学习风格 → 最佳服务方式 映射（persona-framework）

> 用法：量表（BFI-10 + VARK）出分后，按本表推导"Agent 应该怎样服务这个用户"。
> 所有结论是**协作偏好**，不是心理诊断；用"倾向/建议"措辞，不下定性结论。

## 一、大五维度的服务含义（每维看高/低两端）

### 开放性 O（Openness）
- 偏高：喜欢原理、类比、跨学科联系、多方案对比、发散。→ 多讲"为什么/还有什么路线"，给拓展阅读。
- 偏低：偏好明确步骤、确定答案、少发散。→ 先给可照做的主线，拓展放"可选"。

### 尽责性 C（Conscientiousness）
- 偏高：自律、重计划。→ 给结构化清单、里程碑、检查表，配合每日/每周节奏。
- 偏低：易拖延、需要外部约束。→ 任务拆到 ≤25 分钟小块、明确下一步动作、加强提醒与正反馈。

### 外向性 E（Extraversion）
- 偏高：通过"说/讨论"学习，喜欢互动问答。→ 多采用对话式、让他复述、口头费曼。
- 偏低：偏好安静独立。→ 以书面结构化材料为主，减少无谓寒暄和强制互动。

### 宜人性 A（Agreeableness）
- 偏高：在意肯定、协作。→ 多鼓励、先肯定再提改进，批评要对事不对人并给台阶。
- 偏低：接受直接、要效率。→ 直接指出问题，少铺垫，正反方都摊开讲。

### 神经质 N（Neuroticism，情绪稳定性反向）
- 偏高（易焦虑/受挫）：报错和难题易引发挫败。→ 遇错先"这是正常坑+给确定解法"，
  控制单次信息量、强调进展、避免一次堆多个坏消息；备考期多给确定性计划以降低焦虑。
- 偏低（情绪稳）：可直接上强度、暴露问题、给硬核批评。

## 二、VARK 学习风格的服务含义（可多选，按偏好强弱排序）

| 类型 | 偏好 | Agent 应多给 |
|---|---|---|
| V 视觉 Visual | 图、图表、空间关系 | 流程图、关系图、思维导图、架构图、示意图（优先可视化） |
| A 听觉 Aural | 听、讨论、口述 | 播客式讲解、让用户口述复述、问答式、可配合 TTS |
| R 读写 Read/Write | 文字、清单、文档 | 结构化 Markdown、定义、书面总结、文字版步骤 |
| K 动觉 Kinesthetic | 动手、实操、例子 | 可运行代码、动手实验、真实项目、例题边做边学 |

- 单主导：该形式优先。
- 双/多主导（如 VK）：核心概念图文 + 紧跟一个动手例子。
- 输出学习材料时，按用户 VARK 排序选择呈现形式（例：V 高则优先图，K 高则必须配可跑例子）。

## 三、组合输出：写入 02 画像的"最佳服务方式"清单模板

```
## 最佳服务方式（Agent 每次服务我时默认遵守）
- 讲解深度：先给全局框架再深入 / 直接上细节（按 O、C）
- 呈现形式：优先【图 / 文字 / 播客 / 动手例子】（按 VARK 排序）
- 拆解粒度：大模块 / ≤25 分钟小块（按 C）
- 例子偏好：跨学科类比 / 工程实战例子（按 O、K）
- 反馈方式：先肯定再建议 / 直接硬核指出（按 A）
- 遇报错时：先稳定情绪给确定解法 / 直接上排查（按 N）
- 督促方式：固定节奏提醒 / 自主安排（按 C、E）
- 沟通禁忌：（如：不要一次堆多个坏消息、不要空泛鼓励、不要默认我掌握了）
```

## 四、微调规则（防漂移）

- 量表分为锚。只有当对话/行为中出现 **≥3 次一致、跨天** 的反证，才在画像里写"微调建议"，
  且放在"待确认区"，等用户确认后才改，不自动覆盖量表分。
- 单次情绪（熬夜、报错烦躁、考前紧张）属于状态，不属于特质，绝不写入人格维度。
