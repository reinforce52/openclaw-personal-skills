# 熟悉度评分规则（familiarity-rubric）

> 目标：在没有"做题对错流"的前提下，对每个知识点做**可解释、带证据**的 0-4 级估计。
> 禁止凭整体印象打分；每个评级必须能回答"凭什么、什么时候、在哪"。

## 一、五级量表

| 等级 | 名称 | 行为标志（用户实际能做到什么） |
|---|---|---|
| 0 | 未接触 | 无任何笔记/项目/对话记录 |
| 1 | 见过·能认 | 看过资料/视频，能认出概念，看到术语不陌生，但说不出原理 |
| 2 | 能复述·懂概念 | 有自己的笔记/费曼总结，能用自己的话讲清定义、原理、公式来源 |
| 3 | 能应用 | 做过题、写过代码、在项目里跑通过，能独立解决标准问题 |
| 4 | 能教·能迁移 | 多次复现/能讲给别人/能在新场景迁移、能排查相关报错 |

## 二、证据类型与加分

| 证据 | 来源 | 可支撑到 |
|---|---|---|
| 仅收藏/划过/看过一遍 | 学习库浅笔记、视频看完 | 1 |
| 有结构化笔记、概念梳理、公式推导 | 02学习库 | 2 |
| 做过对应习题且有正确记录 | 每日日志/错题本 | 2→3 之间 |
| 项目中实际使用并跑通、有代码片段 | 03项目库 | 3 |
| 多次独立复现 / 输出费曼讲解 / 教会他人 / 跨项目复用 | 多来源 | 4 |

## 三、错题卡点的作用（核心）

- 某知识点出现 1 次卡点：在该知识点下记"薄弱点"，**不直接降级**，但标注"需巩固"。
- 同一类卡点出现 ≥2 次：标记 🔺**高频坑点**，该知识点**评级封顶为 2**，直到出现
  "理解后独立做对/复现成功"的证据，才解除封顶。
- 卡点已解决且有"解决方法+可迁移教训"：作为升到 3 的辅助证据。

## 四、时间衰减（只提示，不偷偷降级）

- 距最近一次接触 >30 天：标 `⚠️生疏风险`，评级保持但提示复习。
- >60 天且无项目锚定：在"建议复习"中置顶。
- 不允许仅因时间流逝自动把等级往下改——必须结合新证据。

## 五、单条知识点记录格式

```
### <知识点名>
- 领域：控制工程 / 机器视觉 / ...
- 熟悉度：3（能应用）  · 最近更新：YYYY-MM-DD
- 证据：
  - [2] YYYY-MM-DD 02学习库/xxx.md 有完整推导
  - [3] YYYY-MM-DD 03项目库/xxx 项目中跑通 yyy
- 关联卡点：🔺同类2次（见03日志 #编号）
- 下一步：xxx
```

## 六、领域汇总

每个领域计算：知识点数量、各等级分布、平均熟悉度、🔺高频坑点数、生疏风险数。
平均熟悉度只做横向参考，必须同时展示分布，避免"平均分掩盖短板"。

## 七、反模式（禁止）

- 因为"用户是这个专业"就默认相关知识点 ≥3。
- 用一次流畅对话就把等级打到 4。
- 没有证据时给评级——此时写"待观察"并列入下次扫描重点。
- 把"看过/收藏"误判为"掌握"。
