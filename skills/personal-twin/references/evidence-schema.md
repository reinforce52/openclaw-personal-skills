# 错题 / 卡点记录格式（evidence-schema）

> 这是能力画像最重要的真实信号。用户入口刻意做轻：一句话【记录卡点】xxx，
> 由 Agent 补全成下面的结构化条目，追加到 `03_错题卡点日志.md`。

## 一、单条结构

```
## [#编号] YYYY-MM-DD HH:mm · <一句话标题>
- 领域：<控制工程 / 机器视觉 / 英语六级 / 编程工程化 / ...>
- 知识点：<具体知识点，用于和 01能力画像 关联>
- 问题类型：概念混淆 / 计算错误 / 代码bug / 环境配置 / 理解偏差 / 审题失误 / 记忆遗忘 / 流程失误 / 其他
- 当时的问题：<我卡在哪、原始现象/报错>
- 错误原因：<根因，尽量挖到"为什么会错"，不止表面>
- 解决方法：<具体怎么解决的，可复现步骤>
- 可迁移教训：<一句话，下次遇到同类怎么避免；这是最有价值的字段>
- 状态：已解决 / 部分解决 / 待复盘
- 出现次数：1（同类再次出现时 +1，≥2 标 🔺高频）
- 关联：[[相关笔记]] [[相关项目]]
```

## 二、重复检测与合并

- 以"领域 + 知识点 + 问题类型"做近似匹配（语义相同即算同类，不要求字面一致）。
- 命中已有条目：不新建，给原条目 `出现次数 +1`，在下方追加一次"复发记录（日期+现象）"，
  次数到 2 时标题加 🔺，并同步到 01 能力画像对该知识点封顶/标红。
- 用户明确说"这次彻底搞懂并独立做对了"：状态改"已解决·已验证"，解除封顶，作为升 3 证据。

## 三、问题类型的统计价值（04成长轨迹用）

- 按"问题类型"聚合，可看出用户主要短板是概念、计算还是工程环境。
- 按"领域"聚合，定位哪一科坑最多。
- 高频复现列表 = 最该优先复习/专项突破的清单。

## 四、写作要求

- 忠实用户原话与真实报错，不虚构根因；根因不确定就写"疑似…，待验证"。
- "可迁移教训"必须是可操作的一句，不写空话（反例："以后要细心"；正例："矩阵求导前先核对维度，维度不符立即停"）。
- 只增不删；修正用追加备注，保留原始记录。
